# 09. 排障与速查表

## 1. 先按层定位

```text
浏览器没有内容
  ├─ HTTP/SSE 层：请求、代理、连接是否正常？
  ├─ Graph 层：运行是否创建，卡在哪个节点？
  ├─ 模型层：活动模型、协议、超时、限流是否正常？
  ├─ RAG 层：是否已索引，过滤和阈值是否正确？
  ├─ 数据库层：业务数据源、权限、SQL 是否正常？
  └─ 报告层：真实结果是否存在，Prompt 是否被截断？
```

不要一看到最终答案不对就立刻改 Prompt。先找到最早出现错误的阶段。

## 2. 症状 → 检查点

| 症状 | 优先检查 | 常见原因 |
| --- | --- | --- |
| 提示没有活动聊天模型 | 模型配置页面、`AiModelRegistry` | 未激活 CHAT 类型模型，配置读取失败。 |
| 模型 401/403 | API Key、baseUrl、代理 | 密钥错误、地址或鉴权协议不兼容。 |
| 模型 404 | baseUrl、completionsPath、modelName | 兼容服务路径不同或模型名不存在。 |
| 模型调用超时 | 网络、代理、超时、模型负载 | 同步/异步客户端代理只配了一边，或报告过长。 |
| JSON 解析失败 | 原始响应、DTO、输出协议 | 输出被截断、带 Markdown、字段类型不匹配。 |
| JSON 能解析但路由错误 | DTO 值和 Dispatcher | 枚举值未校验、模型语义判断错误。 |
| Schema 召回为 0 | 激活数据源、选表、初始化 | 未生成向量、换了 Embedding、阈值过高。 |
| 召回了别的数据 | metadata 过滤 | `agentId` / `datasourceId` / `vectorType` 错。 |
| SQL 一直重试 | 语义错误、数据库错误、计数 | Schema 不足、错误原因没进入重试 Prompt、上限失效。 |
| SQL 能运行但答案不对 | 计划、口径、Evidence、SQL | 指标定义错误、过滤/聚合语义不正确。 |
| SSE 中途停止 | 浏览器断开、sink、Graph error | 客户端取消、异常未转成 error 事件。 |
| 人工反馈后无法恢复 | `threadId`、checkpoint | 使用了新 threadId，检查点已清理或保存失败。 |
| 多轮追问丢上下文 | `conversationId`、ChatMemory | 会话 ID 变化，上一轮无 Planner 输出，窗口淘汰。 |
| Python 分析失败 | Sandbox、镜像、超时、依赖 | Docker 不可用、资源限制、生成代码不符合约束。 |

## 3. 配置速查

| 配置 | 位置/来源 | 说明 |
| --- | --- | --- |
| Spring AI 版本 | 根 `pom.xml` | 当前为 1.1.2。 |
| Spring AI Alibaba 版本 | 根 `pom.xml` | 当前为 1.1.2.2。 |
| 后端端口 | `application.yml` | 默认 8065。 |
| 管理库 | `spring.datasource` | 保存 DataAgent 自身数据，不是分析对象。 |
| VectorStore 类型 | `spring.ai.vectorstore.type` | 默认 simple。 |
| 召回 topK/threshold | `spring.ai.alibaba.data-agent.vector-store` | 表召回与默认召回分开。 |
| SQL 最大重试 | `spring.ai.alibaba.data-agent.max-sql-retry-count` | 防止失败闭环无限循环。 |
| Python Sandbox | `spring.ai.alibaba.data-agent.code-executor.sandbox` | 镜像、并发、依赖源等。 |
| 活动模型 | 管理库 + 模型配置页面 | Chat/Embedding 分别激活。 |

## 5. 概念速查

| 术语 | 一句话解释 |
| --- | --- |
| Token | 模型处理文本的基本计费/长度单位，不等同于字符。 |
| Prompt | 一次模型请求的消息与指令集合。 |
| System Message | 角色和高层规则。 |
| Temperature | 输出随机性参数，不是正确率开关。 |
| Structured Output | 让模型按可解析结构输出，并进行转换/校验。 |
| Embedding | 将文本映射为向量。 |
| VectorStore | 存储向量并进行相似度检索。 |
| RAG | 检索外部资料并加入模型上下文。 |
| metadata filter | 在相似度检索外按租户、类型等做精确过滤。 |
| Tool Calling | 模型请求应用执行一个已声明工具。 |
| MCP | AI 客户端和工具/资源服务之间的标准协议。 |
| Advisor | 拦截并增强 ChatClient 请求/响应的组件。 |
| Reactor Flux | 异步的 0..N 元素流。 |
| SSE | 服务端通过单向长连接向浏览器持续推送文本事件。 |
| Agent | 模型、Prompt、上下文、工具和控制流的工程组合。 |
| Graph State | 当前工作流各节点共享的数据。 |
| Checkpoint | 可用于中断后恢复的状态快照。 |

## 6. 日志检查原则

- 先看最早失败的节点，不要只看最后一条异常。
- 为每次运行关联 `threadId`，为多轮关联 `conversationId`。
- 记录模型名、耗时、状态和必要的长度信息。
- 不记录 API Key、数据库密码和完整敏感数据。
- SQL 可包含敏感常量，生产日志应按数据等级处理。
- 开 DEBUG 前评估 Prompt、Evidence 和模型响应是否会泄露。

## 7. 最小验证命令

运行后端模块测试：

```powershell
.\mvnw.cmd -pl data-agent-management test
```

只运行某个节点测试：

```powershell
.\mvnw.cmd -pl data-agent-management -Dtest=IntentRecognitionNodeTest test
```

检查当前修改：

```powershell
git status --short
git diff -- docs/spring-ai-learning
```

项目有代码格式和覆盖率约束。修改 Java 后不要只依赖 IDE 无报错，应运行对应测试；涉及 Graph 边或真实数据源时，再补充集成验证。

## 8. 问问题时提供哪些信息

为了快速获得帮助，至少提供：

1. 出错节点和页面最后一条正常日志。
2. 异常类型和首个业务相关堆栈位置。
3. `threadId`（敏感环境可脱敏）。
4. 当前 Chat/Embedding 模型类型和是否刚切换。
5. 是否已初始化数据源、召回到哪些表。
6. 是否所有问题都失败，还是某类问题失败。
7. 可复现的最小问题和期望结果。

不要提供真实 API Key、密码或未经脱敏的业务数据。
