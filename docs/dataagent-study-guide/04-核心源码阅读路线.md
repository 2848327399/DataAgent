# 04. 核心源码阅读路线

目标不是一次读完整个项目，而是沿着已经跑通的一次查询逐层向下追踪。每完成一小步，都可以回到页面重新提问验证理解。

## 第 1 步：先看配置与启动

1. `data-agent-management/src/main/java/com/alibaba/cloud/ai/dataagent/DataAgentApplication.java`
2. `data-agent-management/src/main/resources/application.yml`
3. `data-agent-management/src/main/resources/application-h2.yml`
4. 根目录 `pom.xml`

要回答的问题：

- 为什么项目要求 JDK 17？
- `spring.datasource` 连接的是哪一个库？
- H2 profile 与默认 MySQL 配置有什么差别？
- 后端端口为什么是 8065？

## 第 2 步：看前端怎样把问题送出去

1. `data-agent-frontend-nuxt/nuxt.config.ts`
2. `data-agent-frontend-nuxt/app/pages/chat.vue`
3. `data-agent-frontend-nuxt/app/services/graph/index.ts`
4. `data-agent-frontend-nuxt/app/components/chat/ChatWorkflowTimeline.vue`

关注点：`EventSource` 如何建立 SSE 连接、怎样处理 `complete`/`error` 事件、工作流时间线怎样映射节点名称。

## 第 3 步：看后端 API 与图服务

1. `controller/GraphController.java`
2. `service/graph/GraphService.java`
3. `service/graph/GraphServiceImpl.java`
4. `config/DataAgentConfiguration.java`

此阶段应能解释：为什么一次聊天有 `conversationId` 和 `threadId` 两个 ID；为什么取消请求要调用 `/api/stream/stop`；工作流节点和边在哪里注册。

## 第 4 步：按日志阅读 6 个关键节点

建议严格按下面顺序：

1. `workflow/node/EvidenceRecallNode.java`
2. `workflow/node/QueryEnhanceNode.java`
3. `workflow/node/SchemaRecallNode.java`
4. `workflow/node/TableRelationNode.java`
5. `workflow/node/SqlGenerateNode.java`
6. `workflow/node/SqlExecuteNode.java`

每读一个节点都记录三件事：它从图状态读取哪些 key、写回哪些 key、失败后由哪个 Dispatcher 决定下一步。

例如 `SchemaRecallNode` 读取当前 `agentId` 的激活数据源 ID，再通过 `SchemaService` 查询向量化的表/字段文档。因此“召回 0 张表”与业务数据库是否有数据行无直接关系，优先检查 Schema 初始化。

## 第 5 步：再看知识与数据源管理

| 需求 | 后端入口 | 前端入口 |
| --- | --- | --- |
| 新建数据源、测试连接 | `DatasourceController` | `system/data-sources/DatasourceFormDialog.vue` |
| 绑定数据源、选表、初始化 | `AgentDatasourceController` | `system/data-sources/index.vue`、`ExpandedTableManager.vue` |
| 智能体 FAQ / 文档 | `AgentKnowledgeController` | `knowledge/agents.vue` |
| 业务术语、同义词 | `BusinessKnowledgeController` | `knowledge/business.vue` |
| 模型启用与测试 | `ModelConfigController` | `system/model-config.vue` |

## 第 6 步：最后看提示词与数据库访问

- 提示词模板：`data-agent-management/src/main/resources/prompts/`
- 提示词组装：`prompt/PromptHelper.java`
- 数据库连接与查询：`connector/`、`util/DatabaseUtil.java`
- Schema 文档和向量检索：`service/schema/`、`service/vector/`（如存在）

修改提示词前先保存原有版本，并针对一个确定问题做前后对比。例如把“就业率”的口径放进 FAQ 后，观察 `QueryEnhanceNode` 的标准化问题与生成 SQL 是否更稳定。

## 建议的练习

1. 在 `GraphController` 打断点，查看 HTTP 参数进入后端的样子。
2. 在 `SchemaRecallNode` 打断点，查看当前 `agentId` 和召回出的表名。
3. 在 `SqlExecuteNode` 打断点，查看最终 SQL 和动态数据源配置。
4. 在浏览器 Network 面板查看 `/api/stream/search` 的 SSE 请求。
5. 只改一条 FAQ 的文字，重新提同一问题，观察证据召回的差别。

> 不建议一开始修改工作流边或提示词主模板。先能解释现有执行路径，再做最小改动并通过页面测试验证。
