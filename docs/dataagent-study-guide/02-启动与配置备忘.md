# 02. 启动与配置备忘

本章记录一套本地 Windows 环境的稳定启动方式。示例只使用变量名，不记录真实密码或 API Key。

## 1. 已验证的基础环境

| 项目 | 建议/当前验证 |
| --- | --- |
| JDK | JDK 17 |
| 后端构建 | Maven Wrapper：`mvnw.cmd` |
| Node.js | 已使用 Node.js 24 运行前端 |
| 包管理器 | pnpm |
| 后端端口 | 8065 |
| 前端端口 | 3000 |
| 持久化数据库 | MySQL |

## 2. 后端：使用 MySQL 管理库启动

在项目根目录运行，或在 IntelliJ IDEA 的 Maven Run Configuration 中填入同样的命令参数：

```powershell
.\mvnw.cmd -pl data-agent-management "-Dspotless.apply.skip=true" spring-boot:run
```

启动前在 IDEA 的 Run Configuration 中设置环境变量：

```text
DATA_AGENT_DATASOURCE_URL=jdbc:mysql://127.0.0.1:3306/saa_data_agent?useUnicode=true&characterEncoding=utf-8&allowPublicKeyRetrieval=true&useSSL=false&serverTimezone=Asia/Shanghai
DATA_AGENT_DATASOURCE_USERNAME=root
DATA_AGENT_DATASOURCE_PASSWORD=<你的 MySQL 密码>
```

`saa_data_agent` 是项目管理库，不是要让智能体分析的业务库。

## 3. 前端启动

```powershell
cd C:\Users\Administrator\workspace\DataAgent-main\data-agent-frontend-nuxt
pnpm install
pnpm dev
```

首次 `pnpm install` 会下载依赖并执行 `nuxt prepare`，完成标志是类似 `Done in ... using pnpm ...` 的输出。开发服务正常启动后访问：

```text
http://localhost:3000
```

前端终端需要保持运行；关闭终端会停止页面服务。

## 4. H2 与 MySQL 的区别

项目带有 H2 示例配置，可用下面命令体验：

```powershell
.\mvnw.cmd -pl data-agent-management "-Dspring-boot.run.profiles=h2" "-Dspotless.apply.skip=true" spring-boot:run
```

H2 示例使用内存数据库。服务重启后，模型配置、数据源与示例数据可能回到初始状态，因此长期使用应选择 MySQL 管理库。

## 5. 最小可运行检查表

1. 后端日志显示服务在 `8065` 启动。
2. 前端终端显示 Nuxt 的 `Local: http://localhost:3000/`。
3. 前端“模型配置”中有一个已启用聊天模型和一个已启用嵌入模型。
4. 业务数据源测试连接成功，并已绑定当前智能体。
5. 已勾选要查询的数据表，并点击“初始化数据源”。
6. 聊天日志的“初步表信息召回”能召回表名。

## 6. 常见现象与定位

| 现象 | 常见原因 | 处理方式 |
| --- | --- | --- |
| `Port 8065 was already in use` | 旧的后端仍在运行。 | 在 IDEA 停止旧进程，或确认监听 8065 的进程后再停止它。 |
| 页面显示“未检索到相关数据表” | 未绑定当前智能体、未选表，或未初始化 Schema。 | 在带正确 `agentId` 的数据源页面重新选表并初始化。 |
| 显示“没有 active embedding model” | 仅配置了聊天模型。 | 新增并启用嵌入模型；模型更换后重新初始化数据源。 |
| `pnpm install` 停在依赖安装 | Windows 文件占用、杀毒扫描或依赖脚本仍在执行。 | 使用 `pnpm install --reporter=append-only` 查看实际进度；不要在安装过程中关闭终端。 |
| MySQL 模式下配置丢失 | 管理库连接到了错误数据库，或启动时误用了 H2 profile。 | 检查三个 `DATA_AGENT_DATASOURCE_*` 环境变量，并确认未传 `h2` profile。 |

## 7. 重启项目的顺序

1. 启动 MySQL 服务。
2. 启动后端并确认 8065 可用。
3. 启动前端并访问 3000。
4. 在页面确认模型和数据源仍处于启用状态。
5. 如更换过嵌入模型或数据表结构，重新初始化相应数据源。
